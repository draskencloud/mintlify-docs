Nexus follows semantic versioning (`MAJOR.MINOR.PATCH`). Patch releases are backwards-compatible. Minor releases add features without breaking existing APIs. Major releases may break compatibility — check the migration notes below before upgrading.

The authoritative release list is on [GitHub Releases](https://github.com/draskencloud/nexus/releases). This page captures notable changes and upgrade guidance.

---

## Versioning policy

| Component | Compatibility guarantee |
|-----------|-------------------------|
| **Management API** (`/api/v1/*`) | Backwards compatible across minor releases. New fields are added; existing fields keep their semantics |
| **Data plane** behaviour | Behaviour changes appear only in major releases or behind feature flags |
| **Database schema** | Migrations are forward-compatible. Multi-replica rolling upgrades are supported between adjacent minor versions |
| **Configuration file format** (`config/default.toml`) | New keys added in minor releases; existing keys remain valid |
| **Metric names and labels** | Metric names are stable across minor releases. Removals/renames go through a deprecation window of one minor version |

---

## Upgrade procedure

For routine minor / patch upgrades:

1. Review the GitHub release notes for the version range you are crossing.
2. Stage the new image / binary in a non-production environment first.
3. Run the [Production Checklist](/nexus/operations/production-checklist) regression items.
4. Roll out to production using a multi-replica rolling deploy. See [Plan a zero-downtime upgrade](/nexus/operations/runbooks#plan-a-zero-downtime-upgrade).

For major version upgrades, read the migration notes for that version end-to-end before starting.

## Releases

For per-version patch notes consult [GitHub Releases](https://github.com/draskencloud/nexus/releases). The list below summarises the feature surface of the current line.

### Available today

- **Proxy and routing.** HTTP/1.1 reverse proxy with the App → Version → Revision → Endpoint hierarchy. Pass-through and managed-endpoint routing modes. Path rewriting and weighted (canary) traffic routing.
- **Authentication.** API key tokens, JWT (HS256, RS256, RS384, RS512, ES256, ES384) with JWKS support, HTTP Basic auth.
- **Policy engine.** Full inheritance (App → Version → Revision → Endpoint) for auth, rate limits, CORS, IP filter, allowed methods, required scopes, header validation and injection, body size limit, and timeout.
- **Resilience.** Per-Revision circuit breaker, automatic retry on idempotent methods, background health probing, graceful shutdown.
- **Observability.** Prometheus metrics, structured JSON / text logs, async audit pipeline with dead-letter queue, optional OpenTelemetry trace export.
- **Storage.** SQLite (default) and PostgreSQL. In-process or Redis-backed cache for multi-replica deployments.
- **Security.** Server-side TLS termination, mutual TLS to backends via reusable mTLS profiles.
- **Deployment.** Single binary, official Docker image, Helm chart for Kubernetes.

## Deprecation policy

When a feature, configuration key, or API field is deprecated:

1. The deprecation is announced in the release that introduces the replacement.
2. The deprecated surface continues to work for at least one minor version.
3. Logs emit a deprecation warning whenever the deprecated surface is used.
4. The deprecated surface is removed in the following major release.

Deprecation warnings appear in structured logs as `event=deprecation`. Filter for these to stay ahead of removals.

For bug reports, regressions, or upgrade questions, file at [github.com/draskencloud/nexus/issues](https://github.com/draskencloud/nexus/issues). Include the version (`GET /api/v1/version`), build hash, and a reproduction.
