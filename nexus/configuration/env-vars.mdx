All Nexus API Gateway by Drasken Cloud configuration can be controlled via environment variables. This page is the comprehensive reference for every supported `GATEWAY_*` variable and special override variables.

## Naming Convention

```
GATEWAY_<SECTION>__<KEY>
```

- **Prefix:** `GATEWAY_` (always uppercase)
- **Section separator:** double underscore `__`
- **Key names:** uppercase
- **Nesting:** additional `__` for each level (e.g., `GATEWAY_CACHE__REDIS__URL` for `cache.redis.url`)

## .env File

At startup the gateway loads a `.env` file from the current working directory (if present) via [dotenvy](https://docs.rs/dotenvy). Actual shell environment variables take precedence over `.env` values. The file is silently ignored when absent.

```bash
# Example .env for local development
GATEWAY_SERVER__ADMIN_TOKEN=dev-token
GATEWAY_DATABASE_URL=sqlite://./dev.db?mode=rwc
GATEWAY_SERVER__LOG_FORMAT=text
RUST_LOG=nexus=debug
```

**Do not use `.env` files in production.** Use a secrets manager or container environment injection instead.

## Special Variables (Override Behaviour)

These variables have special semantics beyond simple config substitution.

| Variable | Overrides | Description |
|---|---|---|
| `RUST_LOG` | `server.log_level` | Standard `tracing` filter directives. Takes precedence over the TOML `log_level` key. Example: `nexus=debug,tower_http=warn` |
| `GATEWAY_LICENSE_FILE` | `license.license_file` | Path to the license file on disk |
| `GATEWAY_LICENSE_KEY` | _(inline value)_ | Inline license key text. The variable **contains** the key value, not a path |
| `GATEWAY_OTLP_ENDPOINT` | _(activates OTLP)_ | URL of the OTLP collector (e.g., `http://otel-collector:4318`). Activates OpenTelemetry export. Requires binary built with `--features otlp` |
| `GATEWAY_MTLS_PROFILE_<NAME>_CERT_PATH` | _(mTLS profile)_ | Client certificate path for the named mTLS profile |
| `GATEWAY_MTLS_PROFILE_<NAME>_KEY_PATH` | _(mTLS profile)_ | Client key path for the named mTLS profile |
| `GATEWAY_MTLS_PROFILE_<NAME>_CA_PATH` | _(mTLS profile)_ | CA certificate path for the named mTLS profile |

### JWT Secret Environment Variable Names

In `AuthPolicy`, the fields `jwt_secret_env` and `jwt_public_key_env` hold the **name** of an environment variable that contains the actual secret value. They are not the secret itself.

```toml
# In your app's auth policy config:
[auth_policy]
jwt_secret_env = "MY_APP_JWT_SECRET"
```

Then set:

```bash
export MY_APP_JWT_SECRET="the-actual-secret-value"
```

The gateway reads `MY_APP_JWT_SECRET` at runtime and uses its value as the HMAC secret. The `GATEWAY_` prefix is not required for these custom JWT secret variables — you name them and reference them in the policy.

## Error Envelope

All management API error responses use this envelope regardless of which environment variable configuration caused the error:

```json
{
  "status": 400,
  "message": "invalid configuration value for GATEWAY_SERVER__MAX_BODY_BYTES",
  "data": null
}
```

Feature-gate violations (license tier mismatch) return HTTP 402:

```json
{
  "status": 402,
  "message": "feature requires Pro license or higher",
  "data": null
}
```
