---
title: Managed Endpoints
description: Define explicit endpoint rules in managed_endpoint routing mode.
---

In `managed_endpoint` mode, only explicitly registered endpoints are accessible. Requests to unregistered paths return `404`.

## Create an Endpoint

```bash
curl -X POST http://localhost:9090/api/v1/apps/{app_id}/versions/{version_id}/revisions/{revision_id}/endpoints \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -d '{
    "method": "GET",
    "path": "/orders",
    "backend_path": "/v2/orders"
  }'
```

## Fields

| Field | Required | Description |
|-------|----------|-------------|
| `method` | Yes | HTTP method: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `*` (any) |
| `path` | Yes | Path relative to the version's `gateway_path` |
| `backend_path` | No | Overrides the upstream path. Defaults to `path` if omitted |
| `policy_override` | No | Endpoint-level policy that overrides the revision's policy |

## Policy Override

Each endpoint can override any part of the revision's policy:

```bash
curl -X POST .../endpoints \
  -d '{
    "method": "POST",
    "path": "/orders",
    "policy_override": {
      "auth": {
        "auth_type": "jwt",
        "required": true,
        "required_claims": ["sub", "email"]
      },
      "rate_limit": {
        "enabled": true,
        "requests": 100,
        "window_seconds": 60
      },
      "allowed_methods": ["POST"]
    }
  }'
```

## List Endpoints

```bash
curl http://localhost:9090/api/v1/apps/{app_id}/versions/{version_id}/revisions/{revision_id}/endpoints \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN"
```

## Disable an Endpoint

```bash
curl -X PATCH .../endpoints/{endpoint_id} \
  -d '{"is_active": false}'
```

Disabled endpoints return `404` to clients.

## Wildcard Method

Use `"method": "*"` to match any HTTP method on a path:

```json
{
  "method": "*",
  "path": "/health"
}
```
